# Design brief — USR-05 결제 중 강제 종료

> **사후 작성 고지**: 2차 라운드는 G2(Design, 이 문서)와 G3(Design QA, `03-design-review.md`)를 모두 건너뛴 채 `app/settings/premium.tsx` UI를 변경했다. 이 문서는 검수 피드백에 따라 사후 작성했고, `03-design-review.md` 1회차가 이 기능의 첫 G3 검수다. 2차 결과물(현재 코드)의 문제를 먼저 기록하고(§0), 3차 라운드의 목표 상태를 정의한다.
>
> **2회차 변경 (Alex 1회차 Fail 반영)**: B-1 "SDK 응답 대기 중 재진입" 상태 추가·판정 우선순위 명시, B-2·B-3 토스트 문구 수정, S-1 라디오 비활성 표현, S-2 복원·로딩 행, S-4 문체 통일, S-5 결제 버튼 비활성 사유 힌트.

## Design intent

- 사용자가 **다시 결제해도 되는지**를 화면만 보고 판단할 수 있게 한다. "진행 중"과 "이전 구매 확인 필요"를 섞지 않는다.
- 새 컴포넌트·새 토큰 없이 기존 uncertain/timedOut 배너 슬롯 하나로 상태를 표현한다.

## Tokens (defaults)

- 화면: `Screen variant="dark"` (기존)
- 배너: `bg-white/[0.08]`, `rounded-2xl`, 본문 `font-pretendard-medium text-[12px] text-white/85` (기존)
- 상태 확인 버튼: `h-11 rounded-[10px] bg-white/15`, `font-pretendard-bold text-[13px]` (기존)
- 비활성: 결제 버튼 `opacity-50`, 복원·닫기 `opacity-40` (기존), 플랜 라디오는 선택되지 않은 플랜만 `opacity-40` (D-3)

## States

### 배너 판정 우선순위 (위에서 처음 맞는 것 하나만)

1. `isPurchasing` (이 화면에서 시작한 구매가 저장 대기 또는 SDK 대기 중) → 배너 없음, 결제 버튼 Indicator
2. `purchaseStatus === 'timedOut'` → 타임아웃 문구
3. `purchaseStatus === 'uncertain'` → 불확실 문구
4. `isPendingTransaction && isPurchaseInFlight` (SDK 응답이 아직 없는데 이 화면은 구매를 진행하고 있지 않음 — 타임아웃 뒤 화면을 나갔다 재진입) → 처리 대기 문구
5. `isPendingTransaction` (재실행 후 남은 표식) → 이전 구매 문구
6. 그 외 → 배너 없음

`isCheckingStatus`는 위 판정 결과의 문구를 그대로 두고 상태 확인 버튼만 Indicator로 바꾼다.

## Design decisions

- D-1: "이전 구매" 문구는 SDK 응답 대기 중이 아닐 때만 쓴다(S1 해소). 이 화면에서 구매가 진행 중이면 배너 없이 결제 버튼 Indicator로 표현한다.
- D-2: 배너 문구는 JSX 밖에서 우선순위대로 계산한 문자열 하나로 넣는다(S3 해소, §11.2).
- D-3: 플랜 라디오는 결제 버튼과 같은 조건에서 비활성이며, 비활성일 때 **선택되지 않은 플랜만** `opacity-40`으로 낮추고 선택된 플랜은 그대로 둔다(S4 해소 — 어떤 플랜으로 결제가 진행 중인지 계속 보이게).
- D-4: 상태 확인 결과가 "SDK 응답 대기 중"이면 배너를 유지하고 토스트로만 알린다 — 새 UI 요소 없음.
- D-5: 확인이 필요해 결제가 비활성일 때 결제 버튼에 `accessibilityHint`로 사유를 준다(S-5).

## Accessibility

- 상태 확인 버튼: `accessibilityRole="button"`, `accessibilityLabel="결제 상태 확인하기"`, `accessibilityState={{ busy, disabled }}` (기존, 유지). 높이 44pt(`h-11`) 충족.
- 플랜 라디오: `accessibilityState.disabled`를 새 비활성 조건과 일치시키고, 시각적으로도 D-3으로 표현한다.
- 결제 버튼: 확인이 필요해 비활성일 때 `accessibilityHint="결제 상태를 먼저 확인해 주세요."` (D-5). 배너 등장 알림(`announceForAccessibility`)은 쓰지 않는다 — 화면 진입 시 이미 떠 있는 배너를 버튼보다 먼저 읽히는 순서로 충분하다고 판단.
- 배너 문구는 스크린리더가 버튼 앞에서 읽도록 순서 유지.
