# Spec — 다이어리 재설계 "나의 작은 미술관"

## Problem

- 다이어리가 티켓·탑승권·도장 같은 소품 컨셉이라 "AI 도슨트로 전시를 보는 앱"의 결과 맞지 않는다.
- 홈이 날짜 캘린더 중심이라 "어떤 전시를 봤는지"가 한눈에 안 들어온다. 사진이 없는 기록은 빈 칸처럼 보인다.
- 기록 시점을 앱이 끌어주지 않는다. 푸시는 `/diary/{date}`로 가는데 이 화면은 확정된 기록만 보여줘, 아직 기록 전인 사용자는 빈 화면을 만난다.

## Goals

- 다이어리 = **내 벽(전시 액자 모음)**. 본 전시가 액자로 걸리고, 액자마다 미술관 **작품 캡션 라벨**(전시명·장소·날짜·한 줄)이 붙는다.
- 기록 상세 = **도록 페이지**(큰 이미지 → 캡션 → 들은 해설).
- 기록 작성 = **3단계**: 입장(전시·날짜) → 감상(별점·사진) → 캡션(한 줄). 저장하면 내 벽에 액자가 걸린다.
- 관람 직후(도슨트 종료·방문일 저녁 푸시)에 작성 화면으로 곧바로 유도한다.

## Constraints

- 데이터 계층 유지: `visitStore`, `localVisitDb`(SQLite), Supabase `visits`, `visit-photos` 버킷. **스키마 변경 없음.**
- 기존 기록(메모·사진·별점, 동행·키워드가 있으면 그 값)은 잃지 않는다. 새 UI가 쓰지 않는 필드는 읽기만 하고 지우지 않는다.
- 프리미엄 게이트·로그인 게이트 유지(`diary.tsx` 동작 그대로).
- `visit-record-v2`의 미커밋 산출물(`recordDraftStore`, `PhotoGrid`, `ManualRecordForm`, `useEssayStream`, 사진 업로드, `saveRecord`)은 재사용한다.
- 디자인 시스템 토큰만 사용(Deep Plum 단일 강조, Hahmlet 제목). 신규 의존성 없음.

## Non-goals (out of scope)

- Supabase 컬럼 추가, 다른 기기 간 동행·키워드 동기화.
- 서버 푸시 문구·발송 시점 변경(`send-visit-reminders` 그대로, 딥링크 목적지만 클라이언트에서 바꾼다).
- 소셜 공유·타인 벽 보기, 통계 화면.
- "기억에 남는 한 점" 선택(저장 필드가 없어 후속으로 미룬다).
- 몰입모드·해설 생성 로직 변경.

## Users & context

- 프리미엄 로그인 사용자. 전시를 보고 나서(현장 또는 당일 저녁) 짧게 기록하고, 이후 벽을 훑으며 다시 본다.

## Acceptance criteria

### AC-1: 홈 — 내 벽

- **Given** 확정된 기록이 있는 프리미엄 로그인 사용자
- **When** 다이어리 탭에 진입
- **Then** 월별 섹션 헤더 아래에 기록이 액자(포스터 → 내 사진 → 들은 작품 이미지 → 톤 배경 순 대체)와 캡션 라벨(전시명·장소·날짜·한 줄)로 보이고, 액자를 누르면 해당 기록의 도록 상세로 간다.
- 액자 크기는 2~3종을 섞어 벽 느낌을 낸다(같은 기록은 항상 같은 크기).
- 기록이 없으면 빈 벽 + "첫 전시를 걸어보세요" 안내와 '기록하기' CTA.
- 기존 FAB '기록하기'는 유지한다.

### AC-2: 기록을 기다리는 전시

- **Given** 도슨트로 들었지만 기록 전(`pending`)인 관람이 있다
- **When** 다이어리 홈을 본다
- **Then** 벽 맨 위에 "기록을 기다리는 전시" 스트립(전시 포스터·남은 일수)이 보이고, 누르면 그 전시·방문일이 채워진 작성 1단계 완료 상태로 이동한다. 7일 만료 규칙 유지.

### AC-3: 작성 1단계 — 입장

- **When** '기록하기'로 진입
- **Then** 전시 고르기(도슨트 관람·스크랩 추천 / 검색 / 직접 기록)를 한다. 전시를 고르면 다음으로 간다. (구현 시 방문일 선택은 2단계 감상으로 옮겼다 — 전시를 고르는 즉시 이동하는 흐름을 유지하기 위해.)
- 직접 기록은 기존 바텀시트를 그대로 쓴다.

### AC-4: 작성 2단계 — 감상

- **Then** 방문일(기본 오늘, 도슨트 관람은 고정), 별점(0.5점 단위, 필수), 사진(선택, 최대 6)을 입력한다. 위쪽에 이 기록이 걸릴 액자(못·줄·캡션)가 입력에 따라 채워진다.
- 필수는 별점뿐이다(사진 최소 장수 요건 제거).

### AC-5: 작성 3단계 — 캡션

- **Then** 한 줄(100자)을 쓴다(선택). 쓴 글이 있으면 기존 'AI로 다듬기' 사용 가능. 상단에 캡션 라벨 미리보기가 입력에 따라 실시간 갱신된다.
- '기록 남기기' → 액자가 벽에 걸리는 짧은 모션(900ms 내외) 후 다이어리 홈으로, 새 액자가 보인다.
- 단계 사이 이동 시 입력값은 유지되고, 나갔다 들어오면(앱 재시작 포함) 같은 전시의 초안은 복원하지 않아도 되지만 다음 진입에서 깨지지 않는다.

### AC-6: 기록 상세 — 도록

- **Given** 확정 기록
- **When** 액자를 눌러 상세 진입
- **Then** 상단 큰 이미지(스와이프 가능, 포스터+사진), 캡션 블록(전시명·장소·날짜·별점·한 줄), "들은 해설" 목록(재생 가능, `DiaryGuidePlayer` 재사용)이 순서대로 보인다.
- 한 줄·별점·사진을 상세에서 수정·삭제할 수 있다(기존 기능 보존).
- 구 라우트 `/diary/[date]?visit=`는 유지한다.

### AC-7: 관람 직후 유도

- **Given** 몰입모드(도슨트)를 종료했거나 `visit_review` 푸시를 탭했다
- **Then** (a) 몰입 종료 후 홈/탐색 복귀 시 "방금 본 전시를 기록해볼까요?" 배너가 한 번 뜨고 탭하면 AC-2와 같은 곳으로 간다. (b) 푸시 딥링크(`visit_review`)는 해당 날짜에 `pending`이 있으면 작성 화면으로, 확정 기록이 있으면 상세로, 둘 다 없으면 작성 1단계로 간다.

### AC-8: 정리

- 탑승권·도장·티켓 전용 컴포넌트(`BoardingPassPreview`, `VisitTicket*`, `MiniBarcode`, `RecordStepHeader`의 기존 시각 등)와 `DiaryCalendar`를 새 UI로 교체하고 미사용 코드는 삭제한다. `tsc`·`jest` 통과.

## Screens / routes

| Route                | 변경                                                                            |
| -------------------- | ------------------------------------------------------------------------------- |
| `(tabs)/diary`       | 캘린더 → 월별 벽(액자+캡션), 기록 대기 스트립                                   |
| `diary/[date]`       | 티켓 → 도록 상세 (라우트·`?visit=` 유지)                                        |
| `diary/record/index` | 1단계 입장(전시+방문일)                                                         |
| `diary/record/write` | 2단계 감상 + 3단계 캡션(화면 2개로 분리 또는 한 화면 내 스텝 — 브리프에서 결정) |
| 푸시 딥링크          | `visit_review` 목적지 분기                                                      |

## Risks & dependencies

- 벽(masonry) 레이아웃 성능: 기록이 수백 건이어도 월 단위 지연 렌더가 필요(FlashList/FlatList 섹션).
- 이미지 없는 기록의 대체 비주얼(톤 배경 + 전시명 타이포)이 단조롭지 않게 보이도록 브리프에서 정의.
- 개인정보처리방침의 수집 항목(사진·메모)은 변하지 않으므로 수정 불필요 — 단 확인 필요.
- `visit-record-v2`의 미커밋 변경과 같은 파일을 수정하므로 충돌에 주의(재사용 기반으로 진행).
