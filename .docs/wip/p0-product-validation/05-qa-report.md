# mollip P0 제품 검증

검증일: 2026-10-25 / 담당: 프로덕트 기획자

## 범위와 판정 원칙

로그인→전시 선택→AI 해설·대화→종료→기록 저장→재실행 조회, 유료 권한, AI 신뢰성을 점검했다. 현재 작업 트리에는 기존 수정이 다수 있어 이를 포함한 상태로 검사했으며 기존 파일은 변경하지 않았다. 이번 산출물은 검증 보고서다. 기능 수정·상품 정책 확정·배포·운영 데이터 변경은 수행하지 않았다.

- 통과: 실제 실행한 검사에서 기대 결과를 확인한 범위에만 부여한다.
- 실패: 코드에서 수용 기준과 충돌하는 동작/계약을 확인했다. 운영 재현과 구분한다.
- 미검증: 기기·로그인·결제·운영 API 실행 증거가 없다. 코드 존재나 모의 테스트 통과로 대체하지 않는다.

## 발견 사항과 수용 기준

### PAY-01 — 서버 유료 권한 계약 부재

- 근거: `app/(guide)/create-description.tsx:67`의 몰입 시작은 `isPremium`을 검사한다. `supabase/functions/_shared/requireUser.ts`는 JWT로 사용자 존재만 검증한다. `stream-description`, `stream-chat`, `tts`, `extract-text`, `generate-artist-intro`에서 해당 인증을 사용하지만 유료 entitlement 검사는 확인되지 않았다.
- 재현 조건: 유효한 무료 사용자 JWT와 정상 요청 본문으로 해당 함수를 직접 호출한다. 코드에서는 인증 후 외부 AI 호출 경로에 진입한다. 실제 요청·과금은 수행하지 않았다.
- 영향: 유료 기능을 클라이언트 진입 제한만으로 보호할 경우 우회 및 비용 발생 위험. 단, 개별 AI 해설이 무료 제공일 수 있으므로 모든 AI 호출을 유료로 막는 변경은 적절하지 않다.
- 요구사항: 기능별 무료 범위·횟수·유료 범위를 먼저 명세하고 서버가 동일한 정책을 적용한다.
- AC: Given 무료/만료 계정, When 유료 전용 요청을 직접 전송, Then 외부 AI 호출 전에 거절하고 일관된 권한 오류를 반환한다. Given 무료 허용 요청, Then 정의한 한도 내에서 허용한다.

### PAY-02 — 권한 원천 및 오프라인 예외 결정 필요

- 근거: `src/lib/subscriptionVerification.ts`는 마지막 검증 시각부터 72시간을 판단한다. `src/lib/subscription.ts`는 active entitlement와 검증 시각을 조합한다. 한편 `src/store/subscriptionStore.ts:56,69`는 RevenueCat 권한과 `profileIsPremium`을 OR로 합친다.
- 판정: 정책 미검증. 프로필 프리미엄이 운영자 부여 권한인지, 만료·회수·오프라인 유효기간이 무엇인지 이번 확인으로 확정할 수 없다. RevenueCat만이 최종 권한 원천이라고 단정하면 안 된다.
- 영향: 구독 만료 뒤 프로필 권한이 남는 경우의 접근 허용 여부가 불명확하다.
- AC: Given 각 권한 원천의 만료·회수 조합, When 온라인 복귀/앱 재실행/72시간 경과, Then 문서화된 최종 권한과 일치한다. 시간 경계는 72시간 직전·정확히·직후를 각각 검사한다. 구독 만료 시각과 72시간 창 중 무엇을 우선하는지도 확정한다.
- 실결제·복원·환불·계정 전환은 Sandbox 계정에서 별도 확인해야 한다.

### AI-01 — 불확실성 안내와 프롬프트 충돌

- 근거: `src/constants/prompts.ts:118,137`은 “거절하거나 한계를 언급하지 마세요”를 포함한다. 동시에 사실을 지어내지 말라는 지침이 있다. 전시 대화에는 전시 제목만 전달하며 검증된 출품 목록을 제공하지 않는다.
- 재현 조건: 존재하지 않는 작품명·작가 조합 또는 알려지지 않은 전시 출품/참여 작가를 질문한다. 프롬프트 충돌은 확인했으나 모델이 실제로 허위 답변을 생성했는지는 미검증이다.
- 영향: 근거 부족을 숨기거나 추측을 사실처럼 전달할 위험.
- AC: Given 확인할 정보가 부족한 입력, When 해설/대화를 요청, Then 확인 불가를 명시하고 재촬영·작품명 수정·공식 정보 확인 경로를 안내한다. 확인되지 않은 작가·연도·출품 여부를 확정하지 않는다.

### AI-02 — 검색 결과와 실제 출품작 구분 미충족

- 근거: `src/api/artworkSearch.ts`는 검색어로 공개 작품 소스를 통합한다. 전시 ID/출품 관계를 검사하지 않는다. `create-description.tsx`의 선택 흐름은 제목·작가 등을 해설 상태로 옮기며 출처·출품 확인 상태를 함께 전달하지 않는다. `useDescriptionStream.ts`는 수동 해설에 제목·작가를 전달한다.
- 재현 조건: 몰입모드에서 현재 전시와 무관한 유명 작품을 검색해 선택한다. 전시 무관 작품도 해설 경로로 갈 수 있는 구조다. 실제 화면 조작은 미검증이다.
- 영향: 사용자가 일반 검색 작품을 현재 출품작 또는 공식 전시 해설로 오해할 수 있다.
- AC: Given 전시와의 관계를 확인하지 않은 검색 결과, When 결과와 해설을 표시, Then 일반 작품 검색임과 출품 미확인을 표시한다. 공식 출품 근거가 있는 경우에만 확인 상태를 표시하며 작품 데이터 출처와 AI 생성 해설을 구분한다.

### AI-03 — 기술 오류와 작품 식별 실패의 분리 부재

- 근거: `useDescriptionStream.ts`에는 스트림 예외와 재시도 처리가 있지만 식별 성공/불확실/정보 부족의 구조화된 응답 상태는 없다. 사진 입력도 생성 텍스트를 받는다. 촬영 안내에는 “정확한 해설을 생성해요”라는 단정 표현이 남아 있다(`create-description.tsx:452`).
- 영향: 통신 성공을 작품 식별 성공으로 간주할 위험. 흐릿한 사진·비작품 사진의 처리 품질은 미검증이다.
- AC: Given 흐릿한 안내판/빈 사진/복수 작품/허구 작품 입력, When 생성 완료, Then 식별 실패를 일반 작품 해설과 구분하고 재입력 경로를 제공한다. 실패 결과를 정상 감상 이력으로 저장하지 않는다.

### FLOW-01 — 서버 저장 실패의 사용자 가시성 부족

- 근거: `src/store/visitStore.ts:154`의 원격 upsert는 void로 실행하며 오류를 console warning으로만 남긴다. `app/diary/record/caption.tsx:96`은 `saveRecord` 반환 후 완료 연출로 진행한다. 사진 업로드 오류 안내는 별도로 존재한다. 로컬 저장도 존재하므로 서버 실패를 곧바로 기록 전체 유실이라고 판단하지 않는다.
- 재현 조건: 로그인 후 사진 없는 기록을 저장할 때 visits upsert만 실패시키고 로컬 저장은 허용한다. 앱의 완료 표시와 서버 누락을 대조한다. 이후 재연결·재실행 시 복구는 실제 검증 필요.
- 영향: 사용자가 로컬 저장과 계정 동기화 성공을 구분할 수 없다.
- AC: Given 로컬 저장 성공·서버 저장 실패, When 저장 완료, Then 기기 저장/동기화 대기를 구분해 표시한다. When 재연결·앱 재실행, Then 중복 없이 동기화하고 서버 성공 전에 동기화 완료를 표시하지 않는다.

## 권고 우선순위

1. P0: 기능별 무료/유료 정책과 프로필 권한 예외를 확정하고 서버 검사 범위를 맞춘다.
2. P0: 정보 부족·식별 실패·출품 미확인 상태와 카피를 정의하고 프롬프트/화면/저장 조건을 일치시킨다.
3. P0: 실행 환경에서 F-01과 통합 실패 F-03을 완료한다. 자동 검사 통과만으로 P0 완료 처리하지 않는다.

새 기능 구현은 이번 검증 범위에 포함하지 않았다. 본 보고서의 AC는 수정 및 재검증의 제안 기준이며 기존 상품 정책으로 확정된 사항이 아니다.
