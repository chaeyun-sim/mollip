# Spec — 다이어리 기록 상세 (사진 우선 저널)

## 개정 이력

- **rev4 (2026-10-14, 사용자 명시 요청, 티어 S 시각 보정)**: "인디케이터 수정해주고 이미지 영역 안으로 올려줘" — 인디케이터를 사진 안쪽 하단 중앙의 컴팩트한 반투명 알약으로 이동. AC-3r만 갱신, 나머지 rev3 유지.
- **rev3 (2026-10-14, 사용자 명시 요청 — 이전 레이아웃/contain 결정을 덮어씀, M 티어 개정)**: ① 헤더를 absolute로 띄워 사진이 기기 최상단(상태바 뒤)까지 보이게 ② 사진 아래 캐러셀 인디케이터(점) — 썸네일 줄·n/전체 필 제거 ③ 사진 아래 메타를 **중앙 정렬**로 `전시 이름 → 작가 / 위치 → 날짜 → (여백) → 별점 → 후기` 순서. 헤더의 날짜 제목 제거. AC-2/3/5/7이 아래 "rev3 AC"로 대체된다. AC-1/4/6, 읽기 전용 mock 가드, 누락 기록 상태, 정리 이력은 유지.
- 사진은 이제 `contain`이 아니라 `cover`다(상단 중립 레터박스 방지). 비율이 다른 원본은 잘릴 수 있다 — 사용자 요청이 우선.

## Problem

- 다이어리 목록은 미술관 벽 `FrameCard`로 바뀌었지만, 눌러서 들어가는 `app/diary/[date].tsx` → `VisitBlock` → `VisitTicket`은 옛 다크 티켓 화면이다.
- 기록에는 사진이 여러 장 저장될 수 있는데(`thumbnail` + `venuePhotos[]`), 티켓 앞/뒷면에 흩어져 있어 한눈에 볼 수 없다.
- 목록(밝은 벽)과 상세(어두운 티켓)의 톤이 단절된다.

## Goals

- 저장된 사진을 큰 가로 페이지 갤러리로 먼저 보여준다. 사진이 화면의 주인공이다.
- 2장 이상이면 `n / 전체` 인디케이터와 선택 가능한 작은 썸네일을 보여준다.
- 사진 아래에 전시명 · 장소 · 방문일 · 별점 · 메모를 둔다.
- 밝은 캔버스(`bg-light`) + 진한 ink + 절제된 Deep Plum으로 목록과 톤을 맞춘다.
- 기존 기능 보존: 수정/삭제(삭제 확인 Alert), 해설 다시 듣기, 채팅 기록, 단일/다중 방문 라우팅.

## Constraints

- 새 패키지 추가 금지 (`expo-image`, RN `FlatList` 사용).
- 컴포넌트 규칙(`component-convention.md`), 디자인 토큰(`DESIGN_SYSTEM.md`) 준수. 새 색 추가 금지.
- 기존 워킹트리의 무관한 변경 보존. 커밋 금지.
- 실제 저장 기록을 수정/삭제하는 테스트 금지 (dev mock만 사용).

## Non-goals (out of scope)

- 다이어리 목록(벽) 레이아웃, `FrameCard`, `museumWall.ts`.
- 기록 작성(`app/diary/record/*`), `saveRecord`, 업로드 로직.
- 핀치 줌 / 전체 화면 뷰어 / 사진 공유.
- (rev3) `Screen`·`ScreenHeader` 공용 컴포넌트 수정.
- 감상 편집 시트의 기능 변경(사진 교체·티켓 사진 필수 규칙 등). 톤만 밝게 맞춘다.
- 옛 `VisitTicket*` 파일 삭제 (참조만 끊는다).

## Users & context

- 전시를 다녀와 기록을 남긴 사용자가 목록 액자를 눌러 상세로 진입한다. 하루에 기록이 여럿이면 `?visit=` 없이 날짜 진입 시 블록이 세로로 쌓인다.

## 데이터 필드 조사 (DayVisit)

| 필드                     | 의미                                                              | 쓰이는 곳                                                 |
| ------------------------ | ----------------------------------------------------------------- | --------------------------------------------------------- |
| `thumbnail`              | 티켓 사진 또는 기록하기 플로우의 포스터 (`saveRecord`의 `poster`) | 벽 대표 이미지 1순위                                      |
| `venuePhotos[]`          | 티켓 인증 현장 사진 / 기록하기의 작품·공간·나 사진(최대 6)        | 벽 대표 2순위, 로컬 SQLite `local_visit_photos` 순서 보존 |
| `listened[].imageUrl`    | 도슨트로 들은 작품 이미지                                         | 벽 대표 4순위                                             |
| 전시 상세 `heroImageUri` | 전시 포스터                                                       | 옛 티켓의 `ticketPhotoUri ?? heroImageUri` 대체           |

저장 경로(`saveRecord`, `updateVisitPhotos`, `useVisitSync`, `localVisitDb`)는 `thumbnail`과 `venuePhotos`를 **별개 필드**로 보존한다. 읽는 쪽이 둘 중 하나만 보면 사진이 누락되므로 상세는 **두 필드를 합쳐서** 읽는다.

매핑 규칙(`buildVisitPhotos`):

1. `thumbnail` → `venuePhotos[]` 순으로 합친다 (벽 대표 이미지와 같은 첫 장).
2. 공백 문자열 제거, 앞뒤 공백 trim, 완전 동일한 URI는 첫 번째만 남긴다(중복 제거).
3. 결과가 비면 폴백: 전시 포스터(`heroImageUri`) → `listened[].imageUrl` (벽과 같은 순서) — 각각 중복 제거.

## Acceptance criteria

### AC-1: 사진 매핑 유틸

- **Given** `thumbnail`, `venuePhotos`, 빈 값/중복/공백이 섞인 기록
- **When** `buildVisitPhotos(visit, fallbackUri)`를 호출하면
- **Then** thumbnail → venuePhotos 순서로 trim·중복 제거된 배열을 돌려주고, 둘 다 비면 폴백(포스터 → 들은 작품 이미지)을 쓰며, 아무것도 없으면 빈 배열이다. 인덱스 clamp 유틸은 빈 배열에서 0, 범위 밖은 경계로 보정한다.

### AC-2: 가로 페이지 갤러리

- **Given** 사진이 N장(N≥1)인 기록
- **When** 상세에 진입하면
- **Then** 화면 폭의 가로 페이징 갤러리가 맨 위에 나온다. 사진은 `contain`으로 원본 비율을 유지하고 프레임/테두리 장식이 없다. 좌우 스와이프로 넘어간다. 화면 폭/방향이 바뀌어도 현재 장이 유지된다.

### AC-3: 인디케이터와 썸네일

- **Given** 사진이 2장 이상
- **When** 갤러리를 스와이프하거나 썸네일을 탭하면
- **Then** `n / 전체`가 갱신되고 선택 썸네일이 비색상 신호(두께 있는 plum 테두리 + 불투명도 차이)로 구분되며 갤러리가 해당 장으로 이동한다. 1장이면 인디케이터와 썸네일 줄이 없다.

### AC-4: 0장 / 이미지 오류

- **Given** 사진이 0장이거나 URL이 깨진 기록
- **When** 상세를 열면
- **Then** 0장은 전시명 타이포 면의 빈 상태를 보여준다. 깨진 사진은 해당 페이지에 오류 문구와 "다시 시도" 버튼을 보이고 다른 사진은 정상이다. 앱이 멈추거나 빈 화면이 되지 않는다.

### AC-5: 메타·메모 영역

- **Given** 전시명/장소/방문일/별점/메모가 있는 기록
- **When** 갤러리 아래를 보면
- **Then** 전시명(Hahmlet), 장소 · 방문일, 별점(읽기 전용), 메모가 순서대로 나온다. 값이 없으면 해당 줄을 숨기고 "-"는 표시하지 않는다.

### AC-6: 기존 기능 보존

- **Given** 점 세 개 메뉴, 해설 이력, 채팅 이력이 있는 기록
- **When** 메뉴 → 수정/삭제, 들은 작품 탭, 채팅 목록을 사용하면
- **Then** 수정은 감상 편집 시트를 열고, 삭제는 확인 Alert(닫기=취소) 후에만 삭제한다. 재생 가능한 들은 작품은 `onPlayGuide`를 호출한다. 채팅은 밝은 톤으로 그대로 나온다. `?visit=` 파라미터가 있으면 해당 방문 하나만, 없으면 그날 전체 블록을 보여준다.

### AC-7: 화면 톤

- **Given** 상세 화면
- **When** 렌더링하면
- **Then** `Screen variant="warm"` 밝은 배경과 ink 글자, 뒤로가기/헤더가 어두운 색이며 감상 편집 시트도 밝은 표면이다. 옛 티켓·다크 스타일이 남지 않는다.

## rev3 Acceptance criteria (AC-2/3/5/7 대체)

### AC-2r: 상태바까지 이어지는 히어로 갤러리

- **Given** 사진이 1장 이상인 기록
- **When** 상세에 진입하면
- **Then** 사진이 상단 안전 영역 없이 기기 최상단부터 화면 폭 전체로 `cover`로 채워진다(높이 = 폭×1.2, 창 높이 62% 이내). 좌우 스와이프로 넘어간다. 헤더 행이 콘텐츠를 밀지 않는다.

### AC-3r: 사진 안쪽 하단 중앙 캐러셀 인디케이터 (rev4로 갱신)

- **Given** 사진이 2장 이상
- **When** 갤러리를 스와이프하면
- **Then** **사진(히어로) 안쪽 하단 중앙, 아래에서 16px 위**에 작은 반투명 어두운 알약(`bg-black/40`)이 겹쳐 나온다. 활성은 흰 짧은 막대(14×5), 나머지는 흰 50% 점(5×5), 간격 5px. 사진 아래 별도 줄은 없다. 1장 이하면 그리지 않는다. 표시 전용(`pointerEvents="none"`)이라 스와이프를 막지 않고, 접근성 라벨은 `사진 n/N`이다. 점 탭 이동과 썸네일 줄, n/전체 필은 없다(rev3의 탭 가능한 점은 폐기). 사진 아래에는 약 24px 여백 뒤 중앙 정렬 메타가 이어진다.

### AC-5r: 중앙 정렬 메타

- **Given** 전시명/작가/장소/방문일/별점/후기
- **When** 사진 아래를 보면
- **Then** 전시명(Hahmlet) → `작가 / 장소` → 날짜 → 여백 → 별점 → 후기가 모두 중앙 정렬 별도 행으로 나온다. 작가는 전시 상세(`Exhibition.artist`)가 있을 때만 쓰고 작품 작가를 대신 쓰지 않는다. 한쪽만 있으면 슬래시 없이 그 값만, 둘 다 없으면 행을 숨긴다. 날짜는 위치 옆에 중복해 쓰지 않는다. 값이 없는 행은 숨긴다.

### AC-7r: 투명 absolute 헤더

- **Given** 상세 화면
- **When** 렌더링하면
- **Then** 뒤로가기(≥44pt, 안전 영역 아래)가 사진 위에 반투명 면으로 떠 있고 날짜 제목은 헤더에 없다. 점 세 개 메뉴는 사진 우상단 오버레이로 옮겨 제목 중앙을 밀지 않는다. 스크롤해 사진이 지나가면 상태바 영역을 근백색 띠로 덮고 버튼은 밝은 면으로 바뀐다. 편집 시트는 항상 버튼 위에 뜬다. `Screen`/`ScreenHeader` 공용 컴포넌트는 수정하지 않는다.

## Risks & dependencies

- 중첩 스크롤: 세로 ScrollView 안의 가로 FlatList — 방향이 달라 충돌 없음.
- `ScreenHeader`/`Screen`이 `px-6`이라 갤러리는 `-mx-6` 풀블리드.
- 시뮬레이터에서 외부 이미지(picsum)에 네트워크 필요.
