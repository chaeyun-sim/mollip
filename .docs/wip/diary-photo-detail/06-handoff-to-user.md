## Summary

다이어리 기록 상세를 어두운 티켓 화면에서 **사진 우선 저널**로 바꿨다. 저장된 사진(`thumbnail` + `venuePhotos`)을 합쳐 중복 없이 큰 가로 페이징 갤러리로 보여주고, 2장 이상이면 `n / 전체`와 썸네일을 더한다. 사진 아래에 전시명 · 장소 · 방문일 · 별점 · 메모가 나오고, 수정/삭제 확인, 해설 재생, 채팅 기록은 유지했다.

**부작용 복구 상태**: 1차 QA 중 mock 기록 `2026-10-06::t:mock2`에 생긴 스텁은 **로컬 SQLite와 Supabase에서 각 1행만 정확 조건으로 삭제**해 복구했고(재조회로 확인) 벽에 10.06 액자가 돌아왔다. 다만 **`2026-10-10::t:mock1` 스텁이 로컬·원격에 1건씩 남아 있다**(원격 memo `ㅔ`). 내가 만든 것이라는 근거가 없어 승인 범위 밖으로 보고 삭제하지 않았고, 정확한 삭제 조건은 `04-dev-notes.md`에 있다.

## 직접 확인이 필요한 항목 (실기기 / Manual QA Required)

1. 가로 회전·분할 화면에서 현재 장 유지 (시뮬레이터에서 회전 제어 불가 → 코드/단위 테스트만)
2. 깨진 사진 "다시 시도"가 네트워크 복구 후 성공하는지
3. 해설 다시 듣기(들은 작품 행 탭)와 채팅 기록이 실제 데이터로 정상인지 (mock에 해설/채팅 기록이 없음)
4. 같은 날 기록이 여러 개일 때 날짜로 진입한 화면(블록 구분선)
5. 편집 시트에서 사진 교체·저장(업로드를 일으키므로 실행하지 않음)
6. 삭제 후 `router.back()` 동작(취소만 실행)
7. 실제 기록으로 편집 시트 열기/닫기 (mock은 이제 읽기 전용이라 시트 레이아웃을 재확인하려면 실제 기록 필요)
