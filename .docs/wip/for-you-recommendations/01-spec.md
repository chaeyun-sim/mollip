# Spec — 취향 추천 그리드와 전체 보기

## Problem

홈의 취향 추천이 세로 목록으로 보여 전시 추천 그리드와 시각 언어가 다르고, 홈에서 확인할 수 있는 추천 수가 적다. 사용자는 취향 추천을 더 쉽게 둘러볼 수 있는 전용 페이지를 원한다.

## Goals

- 홈 취향 추천을 포스터 1~2개 그리드와 `더 보기` 진입점으로 구성한다.
- `더 보기`에서 저장된 선호 장르에 맞는 전시를 한 점씩 크게 보고 추천 이유를 확인하게 한다.
- 취향 데이터가 바뀌면 기존 선호 설정 캐시와 추천 결과를 갱신한다.

## Constraints

- 기존 `preferred_genres` 기준과 전시 상세 내비게이션을 유지한다.
- 추천 전시 데이터가 없는 경우 일반 전시를 취향 추천처럼 노출하지 않는다.
- 홈 미리보기는 상위 추천 영역에 이미 노출된 전시를 제외한다.

## Non-goals (out of scope)

- 취향 선택 플로우·장르 분류 체계 변경
- 추천 알고리즘 개인화 모델이나 서버 스키마 변경

## Users & context

온보딩 또는 설정에서 미술 취향을 저장한 사용자가 메인 화면에서 추천을 보고 더 많은 추천을 확인한다.

## Acceptance criteria

### AC-1: 홈 미리보기

- **Given** 사용자의 선호 장르와 일치하는 전시가 1개 이상 있다
- **When** 메인 화면에 취향 추천 섹션이 표시되면
- **Then** 최대 2개 전시를 포스터 그리드로 보여주고, 2개 초과 결과가 있을 때 `더 보기`를 제공한다.

### AC-2: 추천 이유가 있는 전체 추천 페이지

- **Given** 사용자가 홈의 `더 보기`를 누른다
- **When** 추천 페이지가 열리면
- **Then** 현재 선호 장르로 매칭된 전체 후보를 큰 큐레이션 카드로 보여주고, 각 카드에 실제 장르 매칭 이유를 표시하며, 전시를 누르면 상세로 이동한다.

### AC-3: 데이터 상태 및 갱신

- **Given** 취향이 없거나 추천 결과가 없다
- **When** 홈 또는 추천 페이지가 열린다
- **Then** 맞춤 추천을 꾸며내지 않고 명확한 빈 상태를 보여준다.
- **Given** 사용자가 취향을 저장하거나 초기화했다
- **When** 저장이 성공하면
- **Then** 메인으로 돌아왔을 때 새 취향 기준으로 추천을 갱신한다.

## Risks & dependencies

- 후보 수는 공개 중인 전시 데이터의 장르 분류 상태에 따라 달라진다.
- 본문 장르 외의 `tags`는 전시 편의·대상 태그라 미술 장르 매칭에 사용하지 않는다.
