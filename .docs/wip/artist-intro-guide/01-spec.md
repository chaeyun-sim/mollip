# Spec — 몰입 모드 작가 소개 인트로 해설

## Problem

몰입 모드로 전시를 감상하기 시작하면 사용자는 곧바로 낱개 작품을 스캔해 해설을 듣는다. 개인전인 경우에도 "이 작가가 누구이고, 어떤 시선으로 이 전시를 보면 좋은지"에 대한 맥락이 전혀 없는 상태에서 첫 작품 해설을 듣게 된다. 작가의 생애·미학적 태도를 먼저 알고 들어가면 개별 작품 해설의 이해도가 크게 올라가지만, 현재 앱에는 그 진입점이 없다.

또한 작가 소개는 사용자별 개인화 요소가 없는 콘텐츠인데, 매 세션마다 Claude API로 새로 생성하면 비용과 대기 시간이 불필요하게 반복된다.

## Goals

- `exhibitions.artist` 값이 채워진 전시(개인전)에서 몰입 모드 재생목록 **맨 첫 트랙**으로 "작가 소개" 해설을 자동 제공한다.
- 해설 내용은 작가의 생애 + 철학적/미학적 스타일 + 이 전시를 감상하는 관점 안내를 담는다.
- 생성은 몰입 시작 화면 진입 시점에 **백그라운드로** 트리거해, 사용자가 기다리는 구간을 만들지 않는다.
- 생성 결과는 `artist` 문자열을 키로 하는 **전역 캐시 테이블**에 저장해 모든 사용자·모든 세션이 재사용한다. 두 번째 이후 관람자는 대기 0.
- `artist` 값이 없는 전시에서는 기능이 완전히 스킵되어, 기존 재생목록 화면과 동작이 100% 동일하다.

## Non-goals (out of scope)

- **단체전 지원 안 함.** `exhibitions.artist`가 비어 있거나 `null`인 전시는 이 기능의 대상이 아니다. 여러 작가를 합쳐 소개하거나, 전시 설명 텍스트에서 작가명을 추론하는 시도를 하지 않는다.
- **`exhibitions.artist` 컬럼의 스키마 마이그레이션·데이터 백필 안 함.** 컬럼과 값은 이미 DB에 반영되어 있다고 전제한다. 앱에서 `artist` 값을 편집·입력하는 UI도 만들지 않는다.
- **몰입 모드 진입 애니메이션(`ImmersiveOverlay`, 화면 어두워지는 연출)은 손대지 않는다.** 타이밍·문구·지속시간 모두 현행 유지.
- **"몰입 준비중" 류의 별도 로딩 화면/문구/타이머 UI를 만들지 않는다.** 캐싱 구조 덕분에 대기 UI가 불필요하다는 것이 합의된 결론이다. 로딩 표현은 재생목록의 해당 트랙 한 줄에 붙는 `ActivityIndicator`가 전부다.
- **인트로 트랙 제목·본문 문구를 스펙에서 고정하지 않는다.** 생성 시 함께 결정하며 정확한 문구는 구현 재량이다.
- **작가 소개에 대한 채팅(도슨트 Q&A) 별도 대응 안 함.** 기존 해설 화면의 채팅 동작을 그대로 따르며 이번에 추가 조정하지 않는다.
- **오프라인 지원, 인트로 해설의 사전 프리페치(전시 상세 화면 등 몰입 모드 밖에서의 생성) 안 함.**
- **캐시 무효화·갱신 UI 안 함.** 한 번 생성된 인트로를 사용자가 다시 생성하도록 하는 기능(생성 실패 재시도 제외)은 범위 밖.

## Users & context

- 대상: 개인전을 관람하며 몰입 모드를 켠 사용자.
- 진입 경로: `app/(guide)/immersive-start.tsx`에서 전시 제목을 **검색 결과에서 선택**하면 `exhibitions.id`가 확보되고(`selectedIdRef`), `immersiveStore.enter(exhibitionId, title)`로 저장된다. 제목을 직접 타이핑만 한 경우 `exhibitionId`는 `null`이다 — 이 경우 `artist`를 조회할 수 없으므로 기능이 스킵된다.
- 재생목록(`app/(guide)/playlist.tsx`)은 몰입 모드의 홈 화면이며, 스캔한 작품이 최신순(reverse)으로 쌓인다. 작가 소개는 이 목록과 별개로 **항상 최상단 고정**이다.
- 재생은 기존 작품 트랙과 동일하게 `store`에 텍스트를 실어 `/description`으로 이동하는 방식을 재사용한다.

## Acceptance criteria

### AC-1: 캐시 미스 시 백그라운드 생성 트리거

- **Given** `artist` 값이 `"이대원(1921-2005)"`으로 채워진 전시를 검색 결과에서 선택했고, 해당 `artist` 키로 저장된 인트로 캐시가 아직 없다
- **When** 몰입 시작 화면에서 "시작하기"를 눌러 몰입 모드에 진입한다
- **Then** 작가 인트로 생성이 백그라운드로 시작되고, 사용자는 그 동안 어떠한 추가 로딩 화면·문구·대기 없이 평소와 동일한 속도로 재생목록 화면까지 도달한다

### AC-2: 생성 완료분은 전역 캐시에 저장되어 재사용된다

- **Given** AC-1의 생성이 완료되어 해당 `artist` 키로 인트로가 캐시에 저장되어 있다
- **When** (같은 기기의 새 세션이든 다른 사용자든) 같은 `artist` 값을 가진 전시로 몰입 모드에 진입한다
- **Then** Claude API 생성 호출이 다시 일어나지 않고, 재생목록의 작가 소개 트랙이 진입 직후부터 곧바로 활성 상태로 보인다

### AC-3: 개인전 재생목록에 작가 소개 트랙이 첫 트랙으로 보인다

- **Given** `artist` 값이 있는 전시로 몰입 모드에 진입해 재생목록 화면에 있다
- **When** 재생목록 섹션을 본다
- **Then** 목록 맨 위에 작가 소개 트랙이 한 줄 표시된다. 스캔한 작품이 0개일 때도 "아직 들은 작품이 없어요" 빈 상태 대신 이 트랙이 보이고, 작품을 여러 개 스캔한 뒤에도 항상 다른 트랙들보다 위에 위치한다

### AC-4: 생성 중인 트랙은 비활성 + 로딩 인디케이터

- **Given** `artist` 값이 있는 전시로 진입했고 인트로 생성이 아직 끝나지 않았다
- **When** 재생목록에서 작가 소개 트랙을 탭한다
- **Then** 트랙 우측에 `ActivityIndicator`가 표시되고 트랙은 `disabled` 상태로 탭에 반응하지 않는다(화면 이동·햅틱 없음). 이때도 별도 안내 문구나 알림은 뜨지 않는다

### AC-5: 생성 완료 시 활성화되고 탭하면 재생된다

- **Given** AC-4 상태에서 재생목록 화면을 벗어나지 않고 머물러 있다
- **When** 인트로 생성이 완료된다
- **Then** 화면을 새로고침하거나 재진입하지 않아도 해당 트랙의 `ActivityIndicator`가 재생 아이콘으로 바뀌어 활성화되고, 탭하면 해설 화면으로 이동해 생성된 작가 소개 본문이 표시되며 TTS로 재생할 수 있다

### AC-6: `artist`가 없는 전시에서는 기능이 완전히 스킵된다

- **Given** `exhibitions.artist`가 비어 있는 단체전이거나, 전시 제목을 검색 선택 없이 직접 타이핑해 `exhibitionId`가 `null`인 상태로 몰입 모드에 진입했다
- **When** 재생목록 화면을 본다
- **Then** 작가 소개 트랙이 아예 렌더링되지 않고, 재생목록의 빈 상태·작품 트랙 목록·플로팅 추가 버튼 동작이 이 기능 도입 전과 완전히 동일하다. 인트로 생성 API 호출도 일어나지 않는다

### AC-7: 생성 실패 시 재시도 가능

- **Given** `artist` 값이 있는 전시로 진입했고 인트로 생성이 네트워크·API 오류로 실패했다
- **When** 재생목록에서 작가 소개 트랙을 본 뒤 탭한다
- **Then** 트랙이 실패 상태(기존 작품 트랙의 실패 표현과 동일한 재시도 아이콘)로 표시되고, 탭하면 생성이 다시 시도된다. 앱이 크래시하거나 재생목록의 다른 트랙 동작이 영향을 받지 않는다

### AC-8: 관람 종료 시 인트로 상태가 초기화된다

- **Given** 작가 소개 트랙이 표시된 상태로 몰입 모드를 사용 중이다
- **When** 헤더 닫기 버튼으로 "전시 관람 종료"를 확인해 몰입 모드를 종료한 뒤, 다른 전시(`artist` 없는 전시)로 새로 몰입 모드를 시작한다
- **Then** 이전 전시의 작가 소개 트랙이 재생목록에 남아 있지 않다(전역 캐시 테이블의 데이터는 유지되지만 현재 세션 상태에는 노출되지 않는다)

## Risks & dependencies

- **`src/types/database.types.ts`에 `exhibitions.artist`가 없다.** 생성된 타입 스냅샷이 DB보다 오래되어 `artist` 컬럼이 Row/Insert/Update 어디에도 없다. 타입 재생성 또는 타입 보강 없이는 `select('artist')`가 tsc를 통과하지 못한다.
- **신규 캐시 테이블(`artist_intros` 등)도 타입에 없다.** 동일한 이슈. 다만 `artist_artworks` 테이블이 이미 "artist 문자열 키 + 전역 캐시 + fire-and-forget upsert" 패턴의 선례로 존재하므로(`src/utils/fetchArtworksForExhibition.ts`) 그 구조를 그대로 따르는 것이 안전하다.
- **캐시 테이블의 RLS 정책**: 모든 사용자가 읽고, 생성 결과를 쓸 수 있어야 한다. 정책이 없으면 캐시 히트가 영구히 발생하지 않아 매번 재생성되는 조용한 실패가 된다 — QA에서 "두 번째 진입 시 즉시 활성"을 반드시 확인해야 한다.
- **백그라운드 생성의 화면 전환 생존**: `immersive-start` → `playlist`는 `router.replace`라 시작 화면이 언마운트된다. 생성 작업이 컴포넌트 언마운트로 중단되면 AC-1/AC-5가 깨진다.
- **기존 SSE 스트리밍 인프라 재사용 여부**: `stream-description`류는 SSE relay + `readSSEStream` 조합이다. 인트로는 타이프라이터 표시가 필수가 아니므로 non-streaming 응답이 더 단순할 수 있으나, 최종 판단은 설계 단계(Sam/Chris)에 맡긴다.
- **`immersiveStore`는 `persist`(AsyncStorage) 대상**이다. 인트로 상태를 스토어에 넣으면 앱 재시작 후 "생성 중" 상태로 영구히 굳는 케이스가 생길 수 있다.
- **동시 생성 중복**: 두 사용자가 같은 작가로 동시에 진입하면 생성이 두 번 일어날 수 있다. 결과가 동일하고 upsert로 수렴하므로 치명적이지 않지만 인지하고 있어야 한다.

## Feature breakdown (for Chris)

1. **AC-1** — 캐시 테이블 및 인트로 생성 Edge Function 준비, 몰입 시작 제출 시 `artist` 조회 → 캐시 미스면 백그라운드 생성 트리거(사용자 대기 없음). 타입 스냅샷 갱신 포함.
2. **AC-2** — 생성 결과를 `artist` 키로 전역 캐시에 저장하고, 진입 시 캐시 히트면 재생성 없이 즉시 사용.
3. **AC-3** — 재생목록 최상단 작가 소개 트랙 렌더링(작품 0개 상태 포함, 항상 첫 트랙 고정).
4. **AC-4** — 생성 대기 상태: `disabled` + `ActivityIndicator`, 탭 무반응.
5. **AC-5** — 생성 완료 시 화면 재진입 없이 활성 전환 → 탭 시 해설 화면 재생.
6. **AC-6** — `artist` 없음 / `exhibitionId === null` 분기에서 트랙 미렌더 + API 호출 없음, 기존 동작 회귀 없음.
7. **AC-7** — 생성 실패 상태 표시 및 탭 재시도.
8. **AC-8** — 몰입 모드 종료(`exit`) 시 인트로 세션 상태 초기화.
