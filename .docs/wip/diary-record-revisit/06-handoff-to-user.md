# Handoff to user

## Summary

기록하기 2단계를 목록이 아닌 **한 번에 한 질문씩 진행하는 플로우**로 바꿨다: 방문일 → 별점 → 오늘 찍은 사진 → 재방문. 헤더는 `2/3`을 유지하고 그 안에 "질문 n / 4" 진행 바를 더했다. 재방문은 이제 "네, 다시 찾았어요 / 아니요, 처음이에요"를 직접 골라야 하고 기존 `isRevisit` boolean으로 저장된다. 시설 평가는 확인 답변을 기다리는 중이라 **넣지 않았다**. 커밋은 하지 않았다.

## UX 변화

- 별점을 고르면 같은 단계에 후기 입력란이 260ms 아래에서 올라오며 나타난다. 별점을 지우면 짧게 사라진다. 후기는 선택 항목이고 최대 100자이며, 다음 캡션 단계의 입력값과 공유된다.

| 질문                         | 컨트롤                                                                       | 다음 조건                           |
| ---------------------------- | ---------------------------------------------------------------------------- | ----------------------------------- |
| 1. 언제 다녀오셨어요?        | 날짜(마호가니, 26px) 탭 → 기존 날짜 피커. 도슨트 고정일은 자물쇠 + 탭 비활성 | 항상                                |
| 2. 전시는 어떠셨나요?        | 별 5개(코코아, 30px), 반 점 지원, `4.5 / 5` 표시                             | 별점 필수                           |
| 3. 오늘 찍은 사진이 있나요?  | 기존 사진 그리드(최대 6장)                                                   | 항상 — 0장이면 주 버튼이 `건너뛰기` |
| 4. 이 전시, 다시 찾으셨나요? | 선택지 2개(올리브 체크 + 굵은 글씨)                                          | 둘 중 하나를 직접 선택              |

- 하단은 항상 `뒤로` + `다음`(또는 `건너뛰기`). 첫 질문의 `뒤로`는 전시 고르기로 나간다. 마지막 질문의 `다음`은 방문일을 확정하고 캡션으로 간다.
- 앞뒤로 가도, 캡션에서 돌아와도 답이 유지되고 마지막 질문으로 복원된다 (`draft.writeStep` 추가, 라우트는 그대로).
- 질문 사이에서는 iOS 스와이프 백을 막고(첫 질문만 허용) Android 뒤로가기는 이전 질문으로 간다.
- 질문 전환은 180ms 페이드뿐이고, 시스템의 "동작 줄이기"가 켜져 있으면 페이드·진행 바 전환이 꺼지도록 코드에 반영했다(기존 `RecordFramePreview`와 같은 방식).
- v2 색 체계 유지: 근백색 / 코코아 / 올리브(선택됨) / 마호가니(날짜·점수), plum은 `다음` 버튼만.
- 사용자 피드백으로 날짜 타이포를 36px→26px, 달력 아이콘을 22px→18px, 별점을 44px→30px로 축소하고 별점 안내 문구를 제거했다.

## 한계 / 미검증 (Manual QA Required)

- **최종 저장 미실행**: 로그인 상태면 원격 행이 생길 수 있어 `기록 남기기`는 누르지 않았다. 캡션 화면까지만 오갔다.
- **시설 평가 미구현**: 사용자의 답(예시인지 실제 필드인지) 대기 중. 답이 오면 질문 1개와 필드를 별도 작업으로 추가한다(질문 목록이 배열이라 진행 바·카운터는 자동으로 따라간다).
- 시뮬레이터에서 확인하지 못한 것: 사진 선택·6장 레이아웃, 날짜 피커 열기, 도슨트 고정일 질문, 동작 줄이기 켠 상태, iOS 스와이프 백 차단·Android 뒤로가기, VoiceOver, 큰 글씨.
- Maestro(iOS)는 radio의 `checked` 상태를 읽지 못해 선택 상태는 스크린샷으로만 확인했다.
- 자동화 중 앱이 한 번 홈 화면으로 나가 있었고(같은 PID라 크래시 아님) 원인은 확정하지 못했다. 앞선 개정의 "첫 탭 유실 1회"도 원인 미확정이다(이번에는 재현되지 않음).
- 마지막 질문에서 `다음` 연타 시 캡션 화면이 중복으로 쌓일 가능성(P2, 기존 버튼과 같은 구조라 이번에 손대지 않음).
- 화면 하단 약 45%가 비어 보인다 — 질문당 컨트롤 1개라는 요구에 맞춘 의도지만 허전하게 느껴질 수 있다.
- `t:mock1` 행과 무관한 기존 변경은 건드리지 않았다.
