# Spec — 관람 기록 플로우 재설계 (티켓 인증 · 관람 확정 대체)

## Problem

- 기록하려면 티켓 사진 + 현장 사진 3장이 필수라, 관람이 드문 사용자는 다이어리를 채우기 어렵다.
- 도슨트 관람(미확정)은 별점·감상·서명 확정 화면이 따로 있어, 기록 경로가 둘로 갈린다.

## Goals

- 인증 없이 "전시 고르기 → 체크인 → 기록" 3단계로 누구나 기록한다.
- mollip만의 요소로 차별화: 스크랩·도슨트 기록 기반 추천, 탑승권이 채워지는 체크인, 도장 별점, 도슨트로 들은 작품을 대상으로 한 영감 한 줄, 저장 시 도장 쿵.
- 도슨트 관람(미확정)도 같은 플로우로 합친다(방문일 고정, 체크인부터).

## Constraints

- 동행·키워드는 기기 로컬 저장(SQLite 컬럼 추가). Supabase 스키마 변경 없음.
- 로그인 사용자는 사진을 기존 `visit-photos` 버킷에 올린다(같은 날 여러 기록이 덮어쓰지 않게 기록별 이름).
- 디자인 시스템 토큰만 사용. 신규 의존성 없음.

## Non-goals (out of scope)

- 티켓 상세(`diary/[date]`)의 레이아웃 변경 — 동행·키워드 표시는 다음 작업.
- Supabase 컬럼 추가, 다른 기기 동기화.

## Acceptance criteria

### AC-1: 전시 고르기

- **Given** 다이어리에서 '기록하기'
- **When** 검색어 없이 진입
- **Then** "도슨트로 다녀온 전시"(미확정 관람)와 "스크랩한 전시"(시작된 것) 추천이 보이고, 하나를 누르면 체크인으로 간다.
- 검색어를 넣으면 `진행 중 / 지난 전시` 결과가 나오고, 맨 아래 "'{검색어}' 직접 기록하기"가 있다.

### AC-2: 직접 기록

- **Given** 검색에 없는 전시
- **When** '직접 기록하기'
- **Then** 같은 화면에서 이름(검색어 자동 입력, 필수)·장소·기간(선택)·포스터(선택)를 입력하고 체크인으로 간다.

### AC-3: 체크인 — 탑승권

- **Then** 상단 탑승권 미리보기에 DATE·GATE(장소)·WITH가 고를 때마다 채워진다.
- 방문일 칩: 오늘·어제·지난 주말·날짜 선택 — 전시 기간 밖·미래 날짜는 숨긴다. 도슨트 관람은 방문일이 고정된다.
- 동행 칩 6종(혼자·친구·연인·가족·동료·모임). 둘 다 골라야 다음.

### AC-4: 기록 작성

- 도장 별점(1~5, 필수), 사진 3칸(작품·공간·나, 선택), 감각 키워드(추천 + 직접 추가, 최대 5), 영감 한 줄(100자, 대상: 전시 전체 + 도슨트로 들은 작품).
- '기록 남기기' → 탑승권 위에 도장이 찍히고 다이어리로. 캘린더에 관람 도장이 생긴다.

### AC-5: 기존 플로우 정리

- 다이어리 FAB → '기록하기'. 미확정 배너 → 기록하기 화면. `verify-ticket`·`confirm-visits`와 그 전용 컴포넌트 삭제.

## Feature breakdown (for Chris)

1. 데이터: `DayVisit.companion/keywords`, SQLite 컬럼, 동기화 보존, `saveRecord`, 기록별 사진 업로드
2. 순수 유틸(+테스트): 방문일 칩 계산, 키워드 정규화
3. 드래프트 스토어 + 화면 3개 + 탑승권 미리보기
4. 다이어리 진입점 교체, 구 화면 삭제
